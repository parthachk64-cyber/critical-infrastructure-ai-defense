# Data card

Three sources, kept apart. Provider data, site identifiers, secrets and licensed PDFs are never committed. Registry: [`src/infra_defense/data/registry.yaml`](../src/infra_defense/data/registry.yaml).

## 1. Study data (the article)

* DOI: 10.1365/s43439-026-00169-5. Availability statement (verbatim): *"The dataset used in this study can be publicly accessible and will be available on request."*
* **Not accessed.** "Available on request" does not establish that any file exists or can be obtained. No author was contacted, no account registered, no PDF requested.
* Dataset names: none; the figures label them "Data set 1-5". Versions, identifiers, ratios, class counts: **unknown, not invented**.
* **Minimum artifacts for exact reproduction:** (a) full text; (b) dataset identifiers and versions; (c) schema and class labels; (d) preprocessing steps; (e) train/test
  membership (record or episode ids); (f) model specification or checkpoint for each series in Figs. 3, 4, 6 including the Hybrid CNN-LSTM; (g) per-record score files or
  confusion counts; (h) timing conditions for Fig. 4 (what was timed, job size, hardware, software); (i) source and denominator of the Fig. 2 percentages.

## 2. Independent water-treatment testbed: iTrust SWaT

* Source: <https://www.sutd.edu.sg/itrust/itrust-labs/datasets/dataset-characteristics/swat/> (checked 2026-11-25). Supported release: **SWaT.A1_Dec 2015** (owner-provided authorized copy; terms are the provider's).
* Verified from that page: 11 days of continuous operation, **7 under normal operation and 4 days with attack scenarios**; values from 51 sensors and actuators; data labelled normal/abnormal; 41 attacks launched in the 4 attack days.
* A Singapore research testbed: it supplies **no** U.S. deployment evidence and is **not** a substitute for the article's data.
* Loader: `infra_defense.data.swat.load_swat_csv` (file layout and label conventions documented in its docstring). Run `infra-defense data-check --swat Normal.csv Attack.csv` to see row counts, span, number of attack runs and **sha256 of each file** (compare with the provider's checksums if it publishes any; none were verified here).
* Label convention implemented: attack intervals are the maximal runs of consecutive rows labelled attack; rows of the last four days labelled normal stay normal. The file has no per-asset ground truth, so an interval is applied to every stage asset P1..P6 (coarser than the release's own attack list; a stated limitation).
* Timestamps are kept as recorded (no offset applied), analysed on a 5-minute mean-resampled grid.
* **No SWaT file was available in this build; no benchmark was run.** Schema tests use a format fixture with fictional values. `prepare --swat` with missing files exits with code 2; it never falls back to generated data.

## 3. Synthetic fixtures (`data/synthetic/`)

Generated by `src/infra_defense/data/synthetic.py` (seed 20260325; regenerate with `python -c "from infra_defense.data.synthetic import write_fixtures; write_fixtures('data/synthetic')"`; checksums in `CHECKSUMS.json`, verified by a test).
Four **fictional** assets (PUMP-01, TANK-02, VALVE-03, FILTER-04), two sensors each (abstract "flow" and "pressure" in arbitrary units), 5-minute grid, 14 days.

| file | content |
|---|---|
| `readings.csv` | observations only: ts, asset_id, sensor, value (a missing sensor is an absent row) |
| `assets.csv`, `maintenance.csv` | operating context available when a score is issued |
| `labels.csv` | labeled incident intervals per asset (evaluation only) |
| `scenarios.csv` | scenario annotations used to explain results (evaluation only) |
| `reviews.csv` | **simulated, fictional** analyst dispositions with decision timestamps (demo only) |

Scenarios: normal operating transitions (S-T1 in development, S-T2, S-T3 in test), a sensor data gap (S-D1), planned maintenance with unusual readings (S-M1, window MW-1), six labeled incidents on eight asset intervals incl. a corroborating pair (INC-1), a maintenance look-alike (INC-2), and a deliberately small deviation (INC-3).
Chronological split by days from stream start: train 0-5, development 5-7 (normal only), test 7-14 (all incidents). Features use only data up to the scoring time; the baseline is fitted on training rows alone; thresholds are set on development normal rows; labels, scenarios and names never enter the feature matrix (tests).
**Intended use:** verify software and metric behaviour. **Limitations:** tiny (8 incident intervals), authored by the same person who wrote the detectors, single seed, Gaussian-like noise; results say nothing about real plants, and nothing about the article's system.
